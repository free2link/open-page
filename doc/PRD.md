# OpenPage 产品需求文档（PRD）

## 1. 产品定义

**产品名称**：OpenPage  
**产品类型**：轻量级、自托管网页发布服务  
**核心技术**：Go、HTTP API、MCP、Web Awesome、SSE、Docker scratch  
**运行方式**：单容器运行，持久化数据存储在 NAS  
**目标用户**：个人开发者、AI Coding 用户、家庭 NAS 用户

### 1.1 产品定位

OpenPage 让用户和 AI Agent 通过 HTTP API 或 MCP 创建、修改、预览和发布网页，并通过普通浏览器访问。

用户可以直接使用 HTML、CSS、JavaScript 和 Web Components 开发页面。OpenPage 负责文件管理、网页托管、版本管理及实时更新。

### 1.2 核心目标

1. **轻量部署**：单个 Docker 容器，无需数据库及独立的前端构建服务。
2. **自由编辑**：允许 AI 创建和修改完整 HTML、CSS、JavaScript 页面。
3. **即时发布**：文件保存后可直接预览，发布成功后浏览器自动更新。
4. **安全恢复**：保存历史发布版本，支持恢复指定版本。
5. **统一操作**：Admin 和 MCP 使用相同的业务功能。
6. **持续运行**：AI 编辑网页期间，已发布页面保持正常访问。
7. **设备兼容**：支持桌面浏览器、移动浏览器及 Android WebView。

## 2. 用户场景

### US-01：创建网页

用户希望通过 Codex 创建一个家庭驾驶舱。

- 用户描述网页需求。
- Codex 调用 MCP 创建页面。
- Codex 写入 HTML、CSS 和 JavaScript。
- OpenPage 保存文件。
- 用户通过预览地址查看效果。
- Codex 发布网页。
- 用户通过 OpenPage 根路径访问网页。

**验收标准**：无需安装前端构建工具即可完成页面创建和发布。

### US-02：修改正在展示的网页

用户的电视正在展示驾驶舱，希望 AI 调整页面布局。

- AI 读取现有页面文件。
- AI 修改工作版本。
- 电视继续展示当前发布版本。
- AI 完成修改并执行发布。
- OpenPage 向浏览器发送更新通知。
- 电视重新加载网页。

**验收标准**：修改工作版本期间，已发布版本保持可访问。

### US-03：恢复故障页面

AI 发布的 HTML 存在错误，导致电视页面异常。

- 用户打开 OpenPage Admin。
- 查看该页面的历史版本。
- 选择此前可用的版本。
- 执行恢复操作。
- OpenPage 恢复对应页面文件并通知浏览器。

**验收标准**：无需 AI、代码编辑器或终端操作即可恢复历史页面。

### US-04：跨设备管理

用户在另一台电脑上使用 OpenCode。

- 连接 OpenPage MCP 服务。
- 获取页面列表及源码。
- 修改页面并发布。
- 原有设备访问地址保持不变。

**验收标准**：所有页面文件均保存在服务端持久化目录。

## 3. 系统功能需求

### 3.1 页面管理

| ID | 功能 | 要求 |
|---|---|---|
| PAGE-01 | 创建页面 | 创建唯一页面 ID 和工作目录 |
| PAGE-02 | 列出页面 | 返回名称、状态、当前版本、访问地址 |
| PAGE-03 | 查看文件 | 支持 HTML、CSS、JS、JSON、图片等文件 |
| PAGE-04 | 修改文件 | 创建、覆盖及删除项目文件 |
| PAGE-05 | 删除页面 | 需要明确确认，并清理关联数据 |
| PAGE-06 | 页面设置 | 支持标题、默认页面及基本配置 |
| PAGE-07 | 默认页面 | 服务器根路径 `/` 展示指定页面 |

每个页面作为独立文件目录管理。

静态资源支持相对路径引用，页面内部可以使用 Web Awesome、UIkit 或其他兼容浏览器的前端资源。

### 3.2 工作版本与预览

每个页面维护独立的工作版本。

要求：

- 编辑操作作用于工作版本。
- 正在发布的文件保持独立。
- 支持预览尚未发布的内容。
- 支持放弃当前修改，重新取得指定历史版本。
- 文件写入采用完整文件替换，防止读取到不完整内容。
- 预览地址需要身份验证。

### 3.3 页面发布

用户或 AI 显式调用发布操作。

发布流程：

1. 检查页面文件和资源路径。
2. 验证入口 HTML 存在。
3. 为本次发布创建版本记录。
4. 保存完整发布文件。
5. 原子切换当前发布版本。
6. 通知在线浏览器。

发布操作需要保证页面文件整体一致。

发布前的检查仅覆盖能够自动判定的问题。浏览器脚本错误、外部服务不可用及设备兼容性问题允许通过历史版本恢复处理。

### 3.4 版本管理

| ID | 功能 | 要求 |
|---|---|---|
| VER-01 | 创建版本 | 每次发布自动创建独立版本 |
| VER-02 | 查看历史 | 显示版本 ID、时间和描述 |
| VER-03 | 查看内容 | 允许读取历史版本文件 |
| VER-04 | 恢复版本 | 重新发布指定历史版本的内容 |
| VER-05 | 重置工作版本 | 将工作文件恢复到指定版本 |
| VER-06 | 版本保留 | 默认保留最近 20 个发布版本 |
| VER-07 | 保护版本 | 允许保护指定版本，防止自动清理 |

历史版本发布后保持不可修改。

恢复操作需要创建新的发布记录，以便继续追踪版本变化。

### 3.5 实时更新

采用 SSE（Server-Sent Events）。

要求：

- 浏览器建立事件订阅连接。
- 页面发布成功后发送更新事件。
- 事件携带页面 ID 和版本 ID。
- 仅通知相关页面的订阅者。
- 浏览器收到更新后重新加载页面。
- 断开连接后支持自动重连。
- 浏览器连接恢复时检查当前版本，避免遗漏发布事件。

实时更新能力由 OpenPage 向发布的 HTML 页面提供，可以通过受控脚本注入实现。

**工作版本文件修改不触发正式展示页面刷新。**

## 4. HTTP API

HTTP API 为 Admin、外部程序和自动化操作提供统一入口。

| Method | Path | 功能 |
|---|---|---|
| GET | `/api/pages` | 获取页面列表 |
| POST | `/api/pages` | 创建页面 |
| GET | `/api/pages/{id}` | 获取页面信息 |
| DELETE | `/api/pages/{id}` | 删除页面 |
| GET | `/api/pages/{id}/files/*` | 读取工作文件 |
| PUT | `/api/pages/{id}/files/*` | 写入工作文件 |
| DELETE | `/api/pages/{id}/files/*` | 删除工作文件 |
| GET | `/api/pages/{id}/versions` | 获取历史版本 |
| POST | `/api/pages/{id}/publish` | 发布工作版本 |
| POST | `/api/pages/{id}/restore` | 恢复历史版本 |
| POST | `/api/pages/{id}/reset` | 重置工作版本 |
| GET | `/api/settings` | 查询系统配置 |
| PUT | `/api/settings` | 修改系统配置 |

文件写入接口需要验证路径、文件大小、访问权限和并发修改状态。

HTTP API 默认需要身份验证，可在 Admin 中关闭普通页面操作的验证。管理台和系统设置始终需要身份验证。

## 5. MCP 服务

使用官方 Go MCP SDK 实现 MCP Server。

通信方式采用 Streamable HTTP。

### 5.1 MCP Tools

| Tool | 功能 |
|---|---|
| `list_pages` | 获取页面列表 |
| `create_page` | 创建页面 |
| `delete_page` | 删除页面 |
| `list_files` | 列出页面文件 |
| `read_file` | 读取工作文件 |
| `write_file` | 创建或修改工作文件 |
| `delete_file` | 删除工作文件 |
| `preview_page` | 获取预览地址 |
| `publish_page` | 发布工作版本 |
| `list_versions` | 获取历史版本 |
| `restore_version` | 恢复历史版本 |
| `reset_draft` | 重置工作版本 |
| `get_page_url` | 获取正式访问地址 |

### 5.2 MCP 设计要求

- Tool 参数应具有明确的 JSON Schema。
- 所有操作返回明确的执行结果和错误信息。
- MCP 与 HTTP API 共用页面、文件和版本管理逻辑。
- 文件管理工具只能访问授权的页面目录。
- 修改操作需要处理并发更新，防止覆盖其他客户端刚刚保存的内容。
- MCP 默认使用访问凭据验证客户端。Admin 可关闭普通页面操作的验证，并提供可复制的客户端配置。
- 支持客户端查询可用工具与能力。

## 6. Admin 管理界面

### 6.1 技术要求

使用：

- 原生 HTML
- CSS
- JavaScript ES Modules
- Web Awesome

Admin 页面和所需组件资源一同打包进 Docker 镜像。

不依赖 React、Vue、Vite 或浏览器外部 CDN。

### 6.2 功能要求

Admin 管理页面包含：

**页面管理**

- 页面列表
- 页面创建与删除
- 访问地址
- 当前发布版本
- 页面预览

**文件管理**

- 文件列表
- 文件内容编辑
- 文件保存
- 文件删除

**版本管理**

- 发布工作版本
- 查看历史版本
- 恢复历史版本
- 重置工作版本

**系统设置**

- API Token 管理
- 默认页面设置
- 服务信息
- 访问权限设置

### 6.3 交互要求

- 管理功能与 MCP Tools 保持一致。
- 危险操作需要确认。
- 显示保存、发布及恢复结果。
- 出现错误时保留编辑内容。
- 页面管理能力不依赖用户发布的 HTML。
- 即使用户页面无法正常执行，Admin 仍然能够访问和恢复版本。

## 7. HTTP 地址设计

默认 HTTP 端口为 `3000`。

| 地址 | 功能 |
|---|---|
| `/` | 当前默认发布页面 |
| `/admin` | 管理界面 |
| `/api/*` | HTTP API |
| `/mcp` | MCP 服务 |
| `/events` | SSE 事件订阅 |
| `/d/{id}/{ticket}/` | 经授权生成的工作版本预览 |
| `/p/{id}/` | 指定页面正式访问地址 |

系统保留管理接口路径，用户网页文件不得覆盖这些路径。

用户上传的网页脚本与管理 API 存在同源安全风险。因此，需要对管理凭据、网页执行权限及来源进行隔离设计。正式页面、管理台、MCP 和草稿预览使用同一个 HTTP 端口，按路径区分。正式页面与草稿通过浏览器沙箱使用独立的安全来源，管理凭据仅在管理台中使用。

## 8. 数据存储

使用文件系统持久化保存数据。

参考结构：

```text
/data/
├── config/
│   └── settings.json
└── pages/
    └── home/
        ├── draft/
        │   ├── index.html
        │   ├── style.css
        │   └── app.js
        ├── versions/
        │   ├── v1/
        │   └── v2/
        └── manifest.json
```

存储要求：

- 容器重新创建后保留数据。
- 版本目录保存完整页面文件。
- 每个页面配置当前发布版本。
- 配置写入采用原子文件替换。
- 版本切换必须保证一致性。
- 禁止通过文件路径访问项目目录以外的内容。
- 文件操作需防止符号链接绕过目录限制。
- 用户资源文件采用白名单路径管理。
- 需要持久保存页面与发布操作的基本记录。

## 9. Docker 部署

### 9.1 基础镜像

采用 Docker 空基础镜像：

`FROM scratch`

### 9.2 构建方式

使用 Docker 多阶段构建。

**构建阶段**

- 使用 Go 官方镜像。
- 编译 Linux 静态可执行文件。
- 构建 Admin 静态资源目录。
- 获取并打包所需 Web Awesome 静态资源。

**运行阶段**

- 基于 `scratch`。
- 仅包含 Go 可执行程序、Admin 静态资源及运行必需文件。
- 使用非 root 用户。
- 监听 HTTP 端口。
- 挂载 `/data` 持久化目录。

### 9.3 运行要求

- 只运行一个 Go 服务进程。
- 无需安装 Go SDK。
- 无需运行 Node.js、Bun、Nginx。
- 无需运行数据库。
- 无需构建用户 HTML 页面。
- 支持通过环境变量配置端口与数据目录。
- 支持 Docker Compose 部署。
- 提供 HTTP 健康检查接口。
- 运行日志输出到标准输出。

镜像体积应尽可能小，并在构建后报告实际压缩体积及解压体积。

## 10. 安全需求

### 10.1 访问控制

- HTTP API 和 MCP 默认验证身份，两个接口的页面操作鉴权可分别关闭。
- Admin 登录和系统设置始终验证身份。
- 页面公开访问与管理权限独立。
- 新数据目录默认管理口令为 `admin`，首次启动时可配置自定义口令。已有数据目录保留原凭据。
- Token 必须支持更新和撤销。
- 禁止在网页源码中保存管理 Token。
- 不允许将管理凭据暴露给用户发布的 JavaScript。

### 10.2 文件安全

- 所有文件访问限定在指定项目目录内。
- 限制单次写入文件大小。
- 限制页面可用存储容量。
- 处理路径遍历和符号链接风险。
- 禁止执行上传的脚本作为服务器程序。
- 用户网页 JavaScript 仅在浏览器中执行。

### 10.3 页面恢复

- 发布前保留当前版本。
- 发布失败时保持原有版本。
- 恢复操作无需依赖 MCP。
- Admin 与用户页面文件独立部署。

## 13. 产品边界

OpenPage 提供网页文件托管、HTTP API、MCP、管理页面、历史版本及实时更新。

用户可以自由编写 HTML、CSS、JavaScript，并通过浏览器支持的 ES Modules 和 Web Components 扩展界面。

React、Vue、Svelte 等需要编译的源码可以由外部开发环境构建后上传发布文件。

OpenPage 不内置远程 IDE、Node.js 包管理环境及通用前端编译系统。

后续扩展功能应保持现有 HTTP API、MCP 和文件存储结构兼容。
